Morapay **v2** is a REST API at `https://api.morapay.io`. Authenticated routes use **HMAC-signed** requests ([Authentication](/getting-started/authentication)). This walkthrough prices a **GHS → USDC buy** quote, then shows the checkout pattern for accepting a payment.

<Tip>
  Create **TEST** API keys in [Dashboard → Developers → API keys](https://business.morapay.io/developers/api-keys). GHS on-ramp quotes require at least **50.00 GHS** in `pay.amount`.
</Tip>

## 1. Create a firm quote

`POST /v2/quotes` returns a `quote_id` you can attach to a buy or use to reason about checkout pricing.

<CodeGroup>

```bash cURL
TIMESTAMP=$(date +%s)
BODY='{"direction":"buy","pay":{"amount":"100.00","currency":"GHS"},"receive_currency":"USDC","rail":"mobile_money","country":"GH"}'
# SIGNATURE = v1= HMAC — see Authentication
curl -s -X POST "https://api.morapay.io/v2/quotes" \
  -H "Content-Type: application/json" \
  -H "Morapay-Key: pk_test_example" \
  -H "Morapay-Timestamp: $TIMESTAMP" \
  -H "Morapay-Signature: v1=$SIGNATURE" \
  -d "$BODY"
```

```javascript Node.js
import { signedFetch } from "./morapay-sign.js"; // see Authentication

const res = await signedFetch("POST", "/v2/quotes", {
  direction: "buy",
  pay: { amount: "100.00", currency: "GHS" },
  receive_currency: "USDC",
  rail: "mobile_money",
  country: "GH",
});
console.log(await res.json());
```

</CodeGroup>

## 2. Start a buy (optional)

Pass `quote_id` to `POST /v2/buys` with `Idempotency-Key` and a `destination_wallet`. Details: [Quotes and ramp](/guides/quotes-and-ramp).

## 3. Collect a checkout payment

For **payment links** and **hosted checkout**, create a link, open a checkout session, then confirm payment:

| Step | Route |
|------|--------|
| Create link | `POST /v2/links` |
| Start checkout | `POST /v2/checkouts` |
| Customer pays (browser) | `POST /v2/public/checkouts/{id}/pay` |
| Confirm on server | `POST /v2/payments/{payment_id}/confirm` |

Full sequence: [Checkouts and payments](/guides/checkouts-and-payments).

## Catalog helpers

Unsigned catalog routes are useful while building UIs:

- `GET /v2/catalog/countries`
- `GET /v2/catalog/chains`
- `GET /v2/catalog/tokens`
- `GET /v2/health` and `GET /v2/ready`
