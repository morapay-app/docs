Merchant routes under **`/v2/*`** require a **signed request** using your API key pair.

## API key pairs

| Key | Prefix | Where it lives |
|-----|--------|----------------|
| Public key | `pk_test_*` / `pk_live_*` | `Morapay-Key` header |
| Secret key | `sk_test_*` / `sk_live_*` | Server env only; used to sign |

Create keys in **Dashboard → Developers → API keys**. Each key is pinned to **TEST** or **LIVE** at creation time.

## Required headers

| Header | Value |
|--------|--------|
| `Morapay-Key` | Your public key `pk_*` |
| `Morapay-Timestamp` | Unix seconds |
| `Morapay-Signature` | HMAC-SHA256 digest prefixed with `v1=` |

Canonical payload:

```
{timestamp}.{METHOD}.{pathWithQuery}.{sha256HexBody}
```

- **Timestamp window:** ±300 seconds
- **Method:** uppercase (`GET`, `POST`, …)
- **Path:** must start with `/` and include the query string exactly as sent, e.g. `/v2/links?page=1` (not URL-encoded variants that differ from the wire request)
- **Body hash:** SHA-256 hex of the **raw** request body; use `""` for GET/DELETE with no body (`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`)

Signing key material: **SHA-256** of the UTF-8 secret `sk_*` as **32 raw bytes** (not the hex string of that digest).

## Node.js example

<CodeGroup>

```javascript Node.js
import { createHash, createHmac } from "node:crypto";

const PUBLIC = process.env.MORAPAY_PUBLIC_KEY ?? "pk_test_example";
const SECRET = process.env.MORAPAY_SECRET_KEY ?? "sk_test_example";
const BASE = "https://api.morapay.io";

function signRequest({ method, pathWithQuery, rawBody = "" }) {
  const timestamp = String(Math.floor(Date.now() / 1000));
  const bodyHash = createHash("sha256").update(rawBody, "utf8").digest("hex");
  const path = pathWithQuery.startsWith("/") ? pathWithQuery : `/${pathWithQuery}`;
  const payload = `${timestamp}.${method.toUpperCase()}.${path}.${bodyHash}`;
  const key = createHash("sha256").update(SECRET.trim(), "utf8").digest();
  const digest = createHmac("sha256", key).update(payload, "utf8").digest("hex");
  return {
    timestamp,
    headers: {
      "Morapay-Key": PUBLIC,
      "Morapay-Timestamp": timestamp,
      "Morapay-Signature": `v1=${digest}`,
    },
  };
}

// GET /v2/keys
const { headers } = signRequest({ method: "GET", pathWithQuery: "/v2/keys" });
const res = await fetch(`${BASE}/v2/keys`, { headers });
```

```bash cURL
TIMESTAMP=$(date +%s)
METHOD=GET
PATH="/v2/keys"
BODY=""
BODY_HASH=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | awk '{print $2}')
PAYLOAD="$TIMESTAMP.$METHOD.$PATH.$BODY_HASH"
# Derive signing key: SHA-256(sk_*) as 32 bytes, then HMAC-SHA256(PAYLOAD)
SIGNATURE="..." # v1=<hex>
curl -s "https://api.morapay.io/v2/keys" \
  -H "Morapay-Key: pk_test_example" \
  -H "Morapay-Timestamp: $TIMESTAMP" \
  -H "Morapay-Signature: v1=$SIGNATURE"
```

</CodeGroup>

Send the same raw body bytes you hashed. Do not re-serialize JSON after signing.

## Idempotency

Money-moving `POST` routes may require `Idempotency-Key`. See [Idempotency](/developer-tools/idempotency).

## Portal access (dashboard only)

Server integrations should use API keys. Dashboard users may call some routes with Bearer session tokens and `X-Business-Id`; that path is not for public integrations.
