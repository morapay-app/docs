---
title: "Idempotency"
description: "Use Idempotency-Key on money-moving v2 POST routes."
---

Routes that **move money** or create irreversible side effects require an **`Idempotency-Key`** header on `POST` (and sometimes on cancel/confirm verbs). OpenAPI marks each operation as `required`, `optional`, or unspecified.

## Rules

1. Generate a unique key per **logical** operation (UUIDv4 is fine).
2. On timeout or `5xx`, **retry with the same key** and the **same JSON body**.
3. Do **not** reuse a key for a different payload — the API may return the first result or reject the call.

## Example

```bash
curl -s -X POST "https://api.morapay.io/v2/buys" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: idem_01HZ_buy_100" \
  -H "Morapay-Key: pk_test_example" \
  -H "Morapay-Timestamp: $TIMESTAMP" \
  -H "Morapay-Signature: v1=$SIGNATURE" \
  -d '{"quote_id":"qt_01","destination_wallet":"0xabc..."}'
```

Common required routes include `POST /v2/buys`, `POST /v2/sells`, `POST /v2/payouts`, and `POST /v2/settlements/withdraw`. See the API reference for the full list.
