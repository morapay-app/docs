title: "Merchant ramp"
description: "Fiat onramp and offramp for registered merchants — quote, initiate, status, and webhooks."

Use the **merchant ramp API** when you want a simple server-to-server flow: quote what the customer pays or receives, start the ramp when they are ready, then poll status or listen on webhooks.

Base path: `/api/v1/merchant/ramp`

Auth is the same as [Merchant API v1](/getting-started/authentication): signed requests with your API key, or portal JWT with `X-Business-Id` for dashboard-backed calls.

<Note>
  This is separate from `POST /api/v1/merchant/quotes/ramp`, which is for **crypto swap-style** quotes (assets and chains). Use **merchant ramp** for **fiat ↔ crypto** corridors (for example GHS and NGN mobile money or bank).
</Note>

## Flow

1. **`POST /ramp/quote`** — price the corridor and show `customerAmount` (and optional `merchantFee` when your account markup applies).
2. **`POST /ramp/onramp`** or **`POST /ramp/offramp`** — start the transaction with the same amount you quoted.
3. **`GET /ramp/transactions/:reference`** — refresh status and payment or deposit instructions.
4. **Webhooks** — subscribe to `ramp.created` and `ramp.status_updated` on your [merchant webhook endpoint](/api-reference/webhooks).

## Endpoints

| Step | Method | Path |
|------|--------|------|
| Quote | `POST` | `/ramp/quote` |
| Onramp | `POST` | `/ramp/onramp` |
| Offramp | `POST` | `/ramp/offramp` |
| Status | `GET` | `/ramp/transactions/:reference` |
| List | `GET` | `/ramp/transactions` |
| OTP (GHS MoMo) | `POST` | `/ramp/transactions/:reference/otp` |
| Config | `GET` | `/ramp/config` |
| Limits | `GET` | `/ramp/limits?currency=ghs` |
| Banks | `GET` | `/ramp/banks?currency=ngn` |

## Rules

- **Initiate** and **OTP** are **LIVE-only**. In TEST you receive `400` with code `RAMP_LIVE_ONLY`.
- Transactions are scoped to your business. Unknown references return **404**.
- **Initiate** requires portal **owner**, **admin**, or **finance** (API keys may initiate when permitted for your integration).
- **Offramp** requires completed owner KYC (same as withdrawals).

## Markup and fees

When your business has ramp markup enabled:

- The **owner** sets the live markup rate in the **merchant portal** (not via this API).
- Quotes and transactions include **`merchantFee`** (`percent`, `amountUsd`, `amountFiat`) when markup applies; otherwise `merchantFee` is `null`.
- **`customerAmount`** is what the customer pays (onramp) or receives in fiat (offramp) after markup.
- Platform pricing is included in the quote; you do not configure provider credentials in the API.

## Quote

`POST /api/v1/merchant/ramp/quote`

| Field | Description |
|-------|-------------|
| `direction` | `onramp` or `offramp` |
| `currency` | Fiat corridor code (for example `ghs`, `ngn`) |
| `amount` | Onramp: fiat amount to quote. Offramp: crypto amount the customer will send |

<RequestExample>

```bash cURL
curl -s -X POST "https://api.morapay.io/api/v1/merchant/ramp/quote" \
  -H "Content-Type: application/json" \
  -H "Morapay-Key: $MORAPAY_PUBLIC_KEY" \
  -H "Morapay-Timestamp: $TIMESTAMP" \
  -H "Morapay-Signature: v1=$SIGNATURE" \
  -d '{
    "direction": "onramp",
    "currency": "ghs",
    "amount": "200"
  }'
```

</RequestExample>

<ResponseExample>

```json 200 OK
{
  "success": true,
  "data": {
    "direction": "onramp",
    "currency": "ghs",
    "amount": "200",
    "customerAmount": "212.40",
    "quotedAmount": "200",
    "quotedCurrency": "ghs",
    "network": "mobile_money",
    "rateLabel": "1 USDC ≈ …",
    "limits": { "min": "10", "max": "50000" },
    "merchantFee": {
      "percent": "1.5",
      "amountUsd": "0.42",
      "amountFiat": "12.40"
    }
  }
}
```

</ResponseExample>

## Onramp

`POST /api/v1/merchant/ramp/onramp`

Start after the customer accepts the quote. Use the **same `amount`** as in the quote.

| Field | Description |
|-------|-------------|
| `destinationWallet` | EVM address to receive crypto |
| `paymentMethod` | `mobile_money` or `bank` |
| `phoneNumber`, `networkProvider` | Required for GHS mobile money (for example `MTN`) |
| `customerName`, `customerEmail` | Optional customer contact |

<RequestExample>

```bash cURL
curl -s -X POST "https://api.morapay.io/api/v1/merchant/ramp/onramp" \
  -H "Content-Type: application/json" \
  -H "Morapay-Key: $MORAPAY_PUBLIC_KEY" \
  -H "Morapay-Timestamp: $TIMESTAMP" \
  -H "Morapay-Signature: v1=$SIGNATURE" \
  -d '{
    "currency": "ghs",
    "amount": "200",
    "destinationWallet": "0x742d35Cc6634C0532925a3b844Bc9e7595f0bEb",
    "customerName": "Ama Mensah",
    "customerEmail": "ama@example.com",
    "paymentMethod": "mobile_money",
    "phoneNumber": "0244000000",
    "networkProvider": "MTN"
  }'
```

</RequestExample>

The response `data` includes a **`reference`**, **`payment`** instructions for the customer, and **`requiresOtp`** when you must call the OTP endpoint.

For NGN bank pay-in, use `"paymentMethod": "bank"` and omit phone fields.

## Offramp

`POST /api/v1/merchant/ramp/offramp`

| Field | Description |
|-------|-------------|
| `amount` | Crypto amount (same as quoted) |
| `bankCode` | From `GET /ramp/banks?currency=…` |
| `accountNumber` | Customer bank account |

<RequestExample>

```bash cURL
curl -s -X POST "https://api.morapay.io/api/v1/merchant/ramp/offramp" \
  -H "Content-Type: application/json" \
  -H "Morapay-Key: $MORAPAY_PUBLIC_KEY" \
  -H "Morapay-Timestamp: $TIMESTAMP" \
  -H "Morapay-Signature: v1=$SIGNATURE" \
  -d '{
    "currency": "ngn",
    "amount": "25",
    "customerName": "Adaeze Okonkwo",
    "bankCode": "058",
    "accountNumber": "0123456789"
  }'
```

</RequestExample>

Response includes **`deposit`** (where the customer sends crypto) and **`payout`** (fiat destination summary).

## OTP (mobile money)

`POST /api/v1/merchant/ramp/transactions/:reference/otp`

```json
{ "otp": "123456" }
```

Use when onramp `requiresOtp` is true (common on GHS mobile money).

## Status and list

**`GET /api/v1/merchant/ramp/transactions/:reference`**

Refreshes upstream status and returns amounts, `customerAmount`, `merchantFee`, and payment or deposit instructions.

**`GET /api/v1/merchant/ramp/transactions`**

Query `page` and `limit` for a paginated history.

Typical statuses: `INITIATED` → `PENDING` → `PROCESSING` → `COMPLETED` | `FAILED`.

## Webhooks

On **LIVE**, register your endpoint for:

| Event | When |
|-------|------|
| `ramp.created` | A ramp transaction was created |
| `ramp.status_updated` | Status or settlement changed |

Verify `Morapay-Signature: sha256=<hex>` with your endpoint secret. Payload `data` uses `object: "ramp_transaction"` with `reference`, `direction`, `status`, amounts, and `merchantFee` when applicable.

See [Webhooks](/api-reference/webhooks) for endpoint management and delivery retries.
